## Task 2 — LoggedTimestamp helper + task-event store

### Goal

| `tests/unit/task-event-store.test.js` | Insert events, verify SQLite row, verify Activity.md append |

### `loggedTimestamp()` spec

```js
{
  local_date:      'YYYY-MM-DD',      // from Date.toLocaleDateString('sv') — Swedish locale = ISO
  local_time:      'HH:MM:SS',        // from Date.toLocaleTimeString('en-GB') — 24h
  utc_offset:      '+HH:MM',          // from Intl.DateTimeFormat offset — handle negative and ±00:00
  timezone:        'Region/City',     // Intl.DateTimeFormat().resolvedOptions().timeZone
  occurred_at_utc: 'YYYY-MM-DDTHH:MM:SSZ'
}
```

All five fields required. Offset computed from `new Date()` and `Intl.DateTimeFormat` — not
hard-coded, not reconstructed.

### `TaskEventStore` spec

`appendEvent(eventFields)`:
1. Generates `event_id` (UUID v4 via `crypto.randomUUID()`).
2. Inserts into `task_events` in a transaction.
3. Appends one line to `<vaultRoot>/Productivity/Activity.md`:
   `[<local_date> <local_time>] <event_type>: <task_title> (<task_id>)\n`
   Creates the file (and `Productivity/` dir) if absent.
4. Returns the inserted `event_id`.

### Test cases for LoggedTimestamp

- Returns an object with all five keys.
- `local_date` matches `YYYY-MM-DD` regex.
- `local_time` matches `HH:MM:SS` regex.
- `utc_offset` matches `[+-]HH:MM` regex.
- `timezone` is a non-empty string.
- `occurred_at_utc` ends with `Z` and parses as a valid ISO instant.
- Calling twice within 1 second returns consistent local_date and timezone.

### Test cases for TaskEventStore

- `appendEvent` inserts a row retrievable by `event_id`.
- All five timestamp fields are present on the inserted row.
- `appendEvent` creates `Productivity/Activity.md` if absent.
- `appendEvent` appends (not overwrites) on a second call.
- The appended line contains the event type and task title.

### `markdown-tasks.js` spec

```js
// Parse a managed-section line into a task object
parseTaskLine('- [ ] Write essay ^task-abc123')
// → { id: '^task-abc123', title: 'Write essay', done: false }

parseTaskLine('- [x] Read chapter ^task-def456')
// → { id: '^task-def456', title: 'Read chapter', done: true }

// Format back to a line (no trailing newline)
formatTaskLine({ title: 'Write essay', id: '^task-abc123', done: false })
// → '- [ ] Write essay ^task-abc123'

// Insert a new task line into managed section content (appended before END sentinel)
insertTaskLine(sectionContent, newLine)

// Remove a line by task ID
removeTaskLine(sectionContent, taskId)

// Replace a line by task ID
replaceTaskLine(sectionContent, taskId, newLine)
```

`sectionContent` is the raw `inner` string from `splitSection`. These functions are pure —
no filesystem I/O.

### `TaskStore` operations

All operations accept `(params, loggedTimestampFn?)` — injectable for tests.

**`createTask({ title, projectId?, startDate?, dueDate?, estimateMinutes?, notePath })`**
1. Generate `id` via `generateTaskId()`.
2. Compute `ts = loggedTimestamp()`.
3. Insert into `tasks` table.
4. Read the target note (Inbox or Project note) via `readNote`.
5. `insertTaskLine` into the inner content.
6. `writeSection` back to disk.
7. `appendEvent({ event_type: 'created', ... })`.
8. Return `{ status: 'success', task }`.

**`editTask({ id, changes })`** — changes is `{ title?, projectId?, startDate?, dueDate?, estimateMinutes? }`
1. Load current task from `tasks` table.
2. Compute `changed_fields` JSON.
3. Update `tasks` row.
4. If `title` changed, `replaceTaskLine` in Markdown.
5. `appendEvent({ event_type: 'edited', changed_fields })`.

**`completeTask({ id })`**
1. Update `status = 'completed'` in `tasks`.
2. `replaceTaskLine` to flip `- [ ]` → `- [x]`.
3. `appendEvent({ event_type: 'completed' })`.

**`reopenTask({ id })`**
1. Update `status = 'open'`.
2. `replaceTaskLine` to flip `- [x]` → `- [ ]`.
3. `appendEvent({ event_type: 'reopened' })`.

**`deleteTask({ id })`**
1. Update `status = 'deleted'`.
2. `removeTaskLine` from Markdown.
3. `appendEvent({ event_type: 'deleted' })`.

**`listTasks({ view, projectId?, query? })`**
- `inbox`: `status = 'open' AND project_id IS NULL`
- `today`: `status = 'open' AND (start_date IS NULL OR start_date <= today)`
- `project`: `status = 'open' AND project_id = ?`
- `completed`: `status = 'completed'`

### Test cases

`markdown-tasks.test.js`:
- `parseTaskLine` round-trips through `formatTaskLine` for open and completed tasks.
- `parseTaskLine` returns null for non-task lines.
- `insertTaskLine` appends new line before END sentinel.
- `removeTaskLine` removes only the matching line.
- `replaceTaskLine` swaps only the matching line.

`task-store.test.js` (all injected, no real DB in unit tests — use in-memory SQLite from Task 1):

- `editTask` with title change updates Markdown and emits `edited` event with `changed_fields`.
- `editTask` with no semantic change does not emit an event.
- `completeTask` flips Markdown checkbox and emits `completed` event.
- `reopenTask` flips checkbox back and emits `reopened` event.
- `deleteTask` removes line and emits `deleted` event.
- `listTasks('inbox')` returns only open inbox tasks.
- `listTasks('today')` excludes tasks with future start dates.

| `tests/renderer/TimerView.test.js` | Countdown display, overflow state, pause/resume button |

### Timer derivation

The renderer computes `secondsRemaining` from:
```
remaining = (plannedMinutes * 60) - Math.floor((Date.now() - startedAtMs) / 1000)
```
A `setInterval(1000)` polls this formula; no accumulated drift. When `remaining ≤ 0`, state
becomes `overflow` and elapsed counts up.

Pause: main process stores `paused_at_utc`. Renderer shows remaining at pause point (frozen).
Resume: main process adjusts `started_at_utc` by `pausedDuration`; renderer resumes formula.

### Resume Packet contents (this increment)

- Task title + project name.
- Previous checkpoint for this task (latest `checkpoints` row where `task_id = ?`), or "No previous checkpoint" if absent.
- Next Action from that checkpoint (editable before starting).
- Minimum Commitment input (default from preferences).

- `pauseSession` sets `paused_at_utc` and `status = 'paused'`.

- `getActiveSession` returns the active session or null.

### Session list query (main process)

```sql
SELECT s.*, c.outcome, c.status AS checkpoint_status, c.next_action,
       t.title AS task_title, p.title AS project_title
FROM sessions s
LEFT JOIN checkpoints c ON c.session_id = s.session_id
LEFT JOIN tasks t ON t.id = s.task_id
LEFT JOIN projects p ON p.id = t.project_id
WHERE s.status = 'ended'
  AND (? IS NULL OR date(s.started_occurred_at_utc) >= ?)
  AND (? IS NULL OR date(s.started_occurred_at_utc) <= ?)
  AND (? IS NULL OR t.project_id = ?)
  AND (? IS NULL OR c.status = ?)
ORDER BY s.started_occurred_at_utc DESC
```
