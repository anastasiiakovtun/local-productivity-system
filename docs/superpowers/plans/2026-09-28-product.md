### Schema (migrations/001-initial.sql)

```sql
CREATE TABLE IF NOT EXISTS preferences (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS tasks (
  id               TEXT PRIMARY KEY,
  title            TEXT NOT NULL,
  status           TEXT NOT NULL DEFAULT 'open',
  project_label    TEXT,
  start_date       TEXT,
  due_date         TEXT,
  estimate_minutes INTEGER,
  created_local_date      TEXT NOT NULL,
  created_local_time      TEXT NOT NULL,
  created_utc_offset      TEXT NOT NULL,
  created_timezone        TEXT NOT NULL,
  created_occurred_at_utc TEXT NOT NULL,
  updated_local_date      TEXT NOT NULL,
  updated_local_time      TEXT NOT NULL,
  updated_utc_offset      TEXT NOT NULL,
  updated_timezone        TEXT NOT NULL,
  updated_occurred_at_utc TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS task_events (
  event_id         TEXT PRIMARY KEY,
  event_type       TEXT NOT NULL,
  task_id          TEXT NOT NULL,
  task_title       TEXT NOT NULL,
  project_label    TEXT,
  changed_fields   TEXT,
  source           TEXT NOT NULL DEFAULT 'app',
  local_date       TEXT NOT NULL,
  local_time       TEXT NOT NULL,
  utc_offset       TEXT NOT NULL,
  timezone         TEXT NOT NULL,
  occurred_at_utc  TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS sessions (
  session_id              TEXT PRIMARY KEY,
  task_id                 TEXT NOT NULL,
  task_title              TEXT NOT NULL,
  project_label           TEXT,
  planned_minutes         INTEGER NOT NULL,
  started_local_date      TEXT NOT NULL,
  started_local_time      TEXT NOT NULL,
  started_utc_offset      TEXT NOT NULL,
  started_timezone        TEXT NOT NULL,
  started_occurred_at_utc TEXT NOT NULL,
  paused_at_utc           TEXT,
  paused_seconds          INTEGER NOT NULL DEFAULT 0,
  ended_local_date        TEXT,
  ended_local_time        TEXT,
  ended_utc_offset        TEXT,
  ended_timezone          TEXT,
  ended_occurred_at_utc   TEXT,
  actual_seconds          INTEGER,
  overflow_seconds        INTEGER DEFAULT 0,
  status                  TEXT NOT NULL DEFAULT 'active'
);

CREATE TABLE IF NOT EXISTS checkpoints (
  checkpoint_id           TEXT PRIMARY KEY,
  session_id              TEXT NOT NULL REFERENCES sessions(session_id),
  task_id                 TEXT NOT NULL,
  project_label           TEXT,
  outcome                 TEXT NOT NULL,
  status                  TEXT NOT NULL,
  next_action             TEXT,
  blocker                 TEXT,
  created_local_date      TEXT NOT NULL,
  created_local_time      TEXT NOT NULL,
  created_utc_offset      TEXT NOT NULL,
  created_timezone        TEXT NOT NULL,
  created_occurred_at_utc TEXT NOT NULL
);
```

### `loggedTimestamp()` output

```js
{
  local_date:      'YYYY-MM-DD',
  local_time:      'HH:MM:SS',
  utc_offset:      '+HH:MM',
  timezone:        'Region/City',
  occurred_at_utc: 'YYYY-MM-DDTHH:MM:SSZ'
}
```

Uses `Intl.DateTimeFormat` for offset + timezone. Never reconstructed — always captured at call time.

### `TaskEventStore.appendEvent(fields)`

1. Generates `event_id` via `crypto.randomUUID()`.
2. Inserts into `task_events` in a transaction.
3. Appends line to `<vaultRoot>/Productivity/Activity.md`:
   `[YYYY-MM-DD HH:MM:SS] <event_type>: <task_title> (<task_id>)\n`
   Creates file + `Productivity/` dir if absent.
4. Returns `event_id`.

### Test cases

`logged-timestamp.test.js`:
- All five keys present.
- `local_date` matches `/^\d{4}-\d{2}-\d{2}$/`.
- `local_time` matches `/^\d{2}:\d{2}:\d{2}$/`.
- `utc_offset` matches `/^[+-]\d{2}:\d{2}$/`.
- `occurred_at_utc` ends with `Z` and parses via `new Date()`.

`task-event-store.test.js`:
- `appendEvent` inserts row retrievable by `event_id`.
- All timestamp fields on inserted row.
- Creates `Activity.md` when absent.
- Appends (not overwrites) on second call.
- Line contains `event_type` and `task_title`.

### Markdown format

```
- [ ] Write essay ^task-abc123
- [x] Read chapter ^task-def456
```

Metadata (project_label, dates, estimate) in SQLite only. No per-task YAML.

### `notePath` for all tasks in this increment

All tasks go to Inbox.md: `<vaultRoot>/<managedFolder>/Inbox.md`. Creates file + dir if absent.

### Operations

- **`createTask({ title, projectLabel?, startDate?, dueDate?, estimateMinutes? })`** — generate id, insert SQLite, insert line into Inbox.md managed section, emit `created`.
- **`editTask({ id, changes })`** — load row, compute `changed_fields`, update SQLite, update Markdown if title changed, emit `edited`. No-op if no fields differ.
- **`completeTask({ id })`** — flip `[ ]`→`[x]`, update status, emit `completed`.
- **`reopenTask({ id })`** — flip `[x]`→`[ ]`, update status, emit `reopened`.
- **`deleteTask({ id })`** — remove line, set `status='deleted'`, emit `deleted`.
- **`listTasks({ view })`** — `inbox`: open; `today`: open + start_date ≤ today or null; `completed`: completed.

### Test cases

`markdown-tasks.test.js`:
- `parseTaskLine` round-trips for open + completed.
- Returns `null` for non-task lines.
- `insertTaskLine` appends before END sentinel.
- `removeTaskLine` removes only matching ID.
- `replaceTaskLine` swaps only matching ID.

`task-store.test.js` (in-memory SQLite + injected mocks):
- `createTask` inserts row + calls writeSection + emits `created`.
- `editTask` title change updates Markdown + emits `edited` with `changed_fields`.
- `editTask` no change → no event.
- `completeTask` flips checkbox + emits `completed`.
- `reopenTask` flips back + emits `reopened`.
- `deleteTask` removes line + emits `deleted`.
- `listTasks('inbox')` excludes completed/deleted.
- `listTasks('today')` excludes future start dates.

### Timer derivation

```js
secondsRemaining = plannedMinutes * 60
  - Math.floor((Date.now() - startedAtMs - pausedMs) / 1000)
// overflow when <= 0; then elapsed = -secondsRemaining
```

`setInterval(1000)` recomputes from timestamps; no accumulated drift.

### Resume Packet (simplified per user direction)

1. Task title (read-only).
2. Project label (read-only, or "—" if unset).
3. Last Checkpoint: Outcome + Status badge — or "No previous checkpoint."
4. Duration selector (number input, 1–180, default from preferences).
5. **Start Session** button.

### Session logging

- `startSession` → insert row `status='active'` + full `started_*` LoggedTimestamp.
- `abandonSession` → update `status='abandoned'` + `ended_*` LoggedTimestamp; append line to Focus Log: `[YYYY-MM-DD HH:MM] Abandoned: <task_title>`.
- `endSession` (Task 8) → update `status='ended'` + `ended_*` + `actual_seconds` + `overflow_seconds`.

### Test cases

`session-store.test.js`: start inserts with `status='active'`; pause sets `paused_at_utc`; resume accumulates `paused_seconds`; abandon sets `status='abandoned'` + ended fields; getActive returns row or null.

`ResumePacketView.test.js`: shows title; shows "No previous checkpoint" when none; shows outcome+status when present; duration defaults to `defaultFocusMinutes`; Start calls `startSession`.

`TimerView.test.js`: displays planned minutes; Pause calls `pauseSession`; Resume calls `resumeSession`; overflow label when `secondsRemaining <= 0`; Abandon calls `abandonSession`.

### Query

```sql
SELECT s.*, c.outcome, c.status AS checkpoint_status, c.next_action
FROM sessions s
LEFT JOIN checkpoints c ON c.session_id = s.session_id
WHERE s.status IN ('ended', 'abandoned')
  AND (? IS NULL OR date(s.started_occurred_at_utc) >= ?)
  AND (? IS NULL OR date(s.started_occurred_at_utc) <= ?)
  AND (? IS NULL OR COALESCE(c.status, s.status) = ?)
ORDER BY s.started_occurred_at_utc DESC
```

### Test cases

## Notes for implementors

- `Activity.md`: task lifecycle events only — not session events.
- Session start IS durably logged (SQLite insert) even when no Checkpoint follows.
- Abandoned sessions write one-line Focus Log entry; no `checkpoints` row.
